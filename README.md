# OTNMS: Industrial OT Network & Agent Monitoring System

**OTNMS** 是一套专为**工业运营技术（OT）网络**、**现场制造工控机（Windows）**以及**自动化线体安全感知**设计的分布式端点监控与深度资产管理系统。

系统由高性能边缘代理（Crystal 语言编写）、跨平台中央服务端（C++17 编写）以及原生桌面控制台（wxWidgets 3.3 编写）构成。在满足 IT 标准监控的同时，具备强大的 **PROFINET DCP 工业网络感知** 与 **万倍级边缘告警收敛** 能力。

## 🏭 OT 工业场景痛点与 OTNMS 解决方案

在自动化线体及制造业数字化转型（IT/OT 融合）落地过程中，生产现场普遍存在以下致命痛点，OTNMS 对此进行了深度的技术攻坚与针对性治理：

### 1. 资产盲区“看不清”
* ❌ **工控机资源异常与假死**：现场工控机资源缺乏长效监控，CPU/内存长期卡死。磁盘空间耗尽或硬件温度过过高，极易导致底层核心应用（如**涂胶控制程序**等）突发报错，随时引发物理死机并导致整条生产线卡节拍、强行停线。
* ❌ **设备闲置与资产浪费**：由于现场缺乏全局的可视化看板，管理层无法准确评估和透视各类工控资产的真实物理利用率与健康度，导致闲置浪费严重。
* ✔️ **OTNMS 解决方案**：采用编译型 **Crystal 语言** 编写轻量化远程代理，不带虚拟机和垃圾回收（GC）长毛刺风险，在确保不影响工控机核心节拍的前提下，无感透视主机资源、存储与核心进程状态。

### 2. 网络风险“防不住”
* ❌ **致命网络环路风暴**：现场维护极易因操作失误插错网线，瞬间引发全网二层网络环路风暴，造成整条自动化线体的工业网络瘫痪与数据丢包。
* ❌ **低级 IP 地址冲突**：新设备上架、供应商或外来维护终端无序接入网络，极易顶掉或冲突掉现场核心生产 PLC/工控机的 IP，造成生产中断。
* ✔️ **OTNMS 解决方案**：代理原生封装 **Npcap 驱动与底层的 L2 监听**。支持特定的网卡接口绑定，直接下沉至 OT 隔离网执行 **PROFINET DCP 工业协议扫描**与 **深度 ARP 探测**，秒级捕获 IP 冲突与违规入网，构筑物理边界防御。

### 3. 跨网断层“排查慢”
* ❌ **IT 与 OT 隐串联**：生产控制网与数据采集网在物理上常发生意外隐串联，故障拓扑极度不明。一旦大流量的 IT 办公网络流量冲击孱弱的 OT 网络，将直接诱发 PLC 掉线导致停线。
* ❌ **抢修定位效率低下**：一旦线体出事，由于缺乏数据支撑，往往只能靠人工分段拔网线排查，各工段互相扯皮，极大地拉长了线体的非计划停线时间。
* ✔️ **OTNMS 解决方案**：内置 **边缘告警收敛引擎**，采用“指纹识别 + 滑动窗口动态去重”机制，实现万倍级告警收敛。出事秒级精炼告警定位，彻底杜绝告警刷屏与互相扯皮。

## 🚀 分布式三层异构架构与核心技术优势

系统采用精密的分布式三层架构，组件间分工明确，通过私有高安全性长连接协议保持长连接：

```text
[ 现场 N * 远程 Agent ] (Windows 系统服务)
        │
        │  (私有高效二进制安全协议 + HMAC-SHA256 挑战认证 + 会话密钥加密)
        ▼
[ 中央 Master 服务端 ] (C++17, 独立运行两套高效服务器)
        │
        ├── (HTTPS REST API / 面向配置与批量管理)
        └── (WebSocket 实时流 / 面向资产状态、告警、进度推送)
        ▼
[ 客户端 GUI 管理平台 ] (C++ / wxWidgets 3.3 原生 Windows 客户端，无 Master 代码硬链接)
```

### 💡 架构核心技术优势

* **多网卡与工业网络感知**：针对工控机双网卡环境（分别连接企业 IT 网与线体 PLC OT 网），Agent 支持网卡接口绑定，直接下沉执行 **PROFINET DCP 扫描**，精准绘制线体设备拓扑。
* **工业级安全通信**：Agent 与 Master 之间采用私有 TCP 协议，基于 **HMAC 身份认证机制与动态密钥对称加密**，严防工业现场指令被劫持或重放攻击。
* **高并发与跨平台**：Master 服务端采用标准 C++17 构建，全面支持 **Windows 和 Linux 环境**部署，无缝适配各类企业服务器架构。
* **通讯量小与部署灵活**：边缘 Agent 日常和 Master 之间**仅保持轻量心跳连接**，只有在接收指令或触发阈值时才进行执行与响应。Master 可以部署在任意网络位置，兼顾带宽节省与架构灵活性。
* **边缘告警收敛引擎**：Master 内部集成了智能告警精炼算法。针对高频重复告警采用**“指纹识别 + 滑动窗口去重”机制**，成功实现告警信息数千倍级收敛，避免 Zabbix 刷屏与日志撑爆，同时确保关键告警不丢失。

## 🔒 核心加密安全矩阵

为应对严苛的工业现场网络对抗，防止针对 PLC 和工控机的控制指令被劫持、篡改或重放，OTNMS 构建了全方位的安全矩阵：

* **私有高效二进制安全协议**：Agent 与 Master 之间的通信基于单条持久 TCP 连接。数据包分为明文固定报头与强加密载荷。支持 `REQUEST`、`RESPONSE`、`HEARTBEAT`、`REPORT`、`AUTHENTIFICATION` 等数据格式。
* **双向握手认证**：连接建立时，进行基于 **HMAC-SHA256 的挑战-应答（Challenge-Response）** 动态机制和预共享密钥校验。认证通过后，**动态协商生成单次会话的 AES-256-CBC 会话密钥**。
* **高性能外部 DLL**：通过 C FFI 绑定调用专有的加密模块 DLL，为敏感凭据的分发提供额外的非对称加密（RSA/AES）屏障。
* **API 中间件防御**：Master HTTP 服务器集成高级安全中间件：配置有 **IP 白名单机制** 以及 **每 IP+路径 20 请求/秒 的硬性速率限制**。

## 🛠️ 关于 Agent 技术选型与架构说明

工业现场部署有大量工控机（IPC），它们各自承担着**涂胶控制、视觉检测、工艺参数监控**等不同的核心生产职能，而非专门用于运行安全探针（Agent）的服务器。Agent 程序必须作为“透明插件”融入到这些已经跑着各种高负载工业软件的现有环境中。这种特殊的共生关系，使得 Agent 的技术选型变得极其谨慎和重要。

为了确保核心业务的绝对稳定，Agent 的加入必须遵循**“零干扰、高隐蔽、强穿透”**的原则：

### 1. 极简依赖，规避冲突风险
* ⚠️ **现状痛点**：脚本语言（如 Python）依赖多，打包体积大（动辄数百 MB），在 Windows 现场极易与工控机已有环境变量冲突。
* ✨ **选型优势**：采用原生编译型语言（Crystal），**无外部重度依赖**，最终生成的安装包极小，支持绿色单文件部署，彻底杜绝环境污染。

### 2. 极致性能，零算力争抢
* ⚠️ **现状痛点**：Python 存在全局解释器锁（GIL），作为脚本语言天生性能低下；Java/C# 需安装臃肿的运行时（JVM/.NET），内存占用高且 GC（垃圾回收）停顿不可控，极易引发上位机软件卡顿。
* ✨ **选型优势**：纯高性能编译性语言，**无虚拟机开销**，内存开销极低（运行期仅数 MB），绝不争抢工控机宝贵的 CPU 与内存资源。

### 3. 二进制编译，保障算法安全
* ⚠️ **现状痛点**：脚本语言源码完全开放或极易被工具逆向还原，导致探针的内部防御逻辑、资产白名单和现场机密配方外泄。
* ✨ **选型优势**：源码直接被 LLVM 构建并编译为底层机器指令（二进制 Executable），**具备高强度抗反编译能力**，强力保障核心数字资产安全。

### 4. 零开销绑定，穿透二层工业网
* 🎯 **核心诉求**：Agent 必须调用 Npcap/Raw Socket 发送原始套接字，执行 **PROFINET DCP** 等底层二层网络拓扑扫描。
* ✨ **选型优势**：语言天然支持 **C-Bindings（C 语言原生绑定）**。无需多层低效封装，可直接映射内存结构体，原生、高并发地操纵底层网络捕获驱动。
